# Sprint 42A — Professional DOCX Page Engine

## Цель

Довести DOCX-viewer до профессиональной листовой модели: документ должен сохранять одну и ту же вёрстку на macOS и Android, а мобильная версия должна масштабировать лист, а не пересобирать строки под ширину экрана.

## Что изменено

### Фиксированная листовая модель

- DOCX больше не уменьшается за счёт сжатия полей и повторного reflow текста на узком экране.
- Введён фиксированный логический размер страницы из `w:pgSz`.
- Поля страницы берутся из `w:pgMar` и применяются одинаково на desktop и mobile.
- На мобильных экранах лист масштабируется целиком через page scale-to-width.
- Это устраняет главный дефект: переносы строк на телефоне больше не должны становиться другими только из-за ширины экрана.

### Корректный размер шрифта DOCX

- Исправлена конвертация `w:sz`: Word хранит размер в half-points, теперь используется деление на `2.0`, а не завышение.
- Базовый размер абзаца приведён к 12 pt.
- Межстрочный интервал и интервалы между абзацами приближены к Word-layout.
- Заголовки стали ближе к документным размерам, а не к ebook-типографике.

### Page breaks

- Добавлена поддержка ручных разрывов страниц `<w:br w:type="page" />`.
- Документ разбивается на отдельные бумажные страницы по явным page breaks.
- Это особенно важно для договоров и приложений/спецификаций, где приложение должно начинаться с новой страницы.

### Таблицы

- Таблицы стали компактнее и ближе к Word:
  - уменьшены padding и кегль таблиц;
  - числовые колонки выравниваются по центру;
  - `ИТОГО`/`TOTAL` выравнивается вправо;
  - учитывается `w:gridSpan` как приближение к объединённым ячейкам;
  - учитывается continuation для `w:vMerge`;
  - `w:tblGrid` продолжает использоваться для относительных ширин колонок.
- Полная поддержка настоящего colspan в Flutter Table пока не реализована; это следующий возможный подпункт, если конкретные DOCX с объединёнными ячейками всё ещё отличаются от Word.

### Header/footer

- Header/footer больше не участвуют в общем reflow документа.
- Они рендерятся внутри листа и масштабируются вместе со страницей.
- Текст колонтитулов стал более компактным.

## Что не трогалось

- PDF / DJVU / EPUB / FB2 / TXT не менялись.
- EPUB internal links не менялись, они уже исправлены.
- CHM не дорабатывался.
- Relay и серверный код не менялись.
- GitHub Actions, naming и версионирование сборок не менялись.
- Проценты прочтения в библиотеке не менялись.

## Relay

Обновлять relay через SSH не нужно.

## Проверки в GitHub Actions

Должны пройти обычные проверки проекта:

- dependency resolution;
- `flutter analyze`;
- `flutter test`;
- Android build;
- macOS build.

## Ручная проверка

### macOS

1. Открыть `Договор_поставки.docx` в ReadArc.
2. Открыть тот же файл в системном просмотрщике macOS / Pages.
3. Сравнить:
   - первую страницу договора;
   - блок реквизитов;
   - переход к приложению;
   - таблицу спецификации;
   - строку `ИТОГО`;
   - подписи;
   - нижние колонтитулы.

### Android

1. Открыть тот же DOCX.
2. Проверить, что страница выглядит как уменьшенный лист, а не как переформатированный поток текста.
3. Проверить, что переносы строк совпадают по логике с desktop.
4. Проверить вертикальный скролл и прогресс.
5. Проверить выделение и копирование текста через системный SelectionArea.

## Известные ограничения после Sprint 42A

- Автоматическая пагинация по высоте страницы пока не является полноценным Word-layout engine; сейчас поддерживаются явные page breaks и листовая модель.
- Объединённые ячейки таблиц приближены через `gridSpan`, но не являются полноценным colspan-renderer.
- Legacy `.doc` не является целью Sprint 42A и остаётся на прежнем fallback/native-OLE text path.
