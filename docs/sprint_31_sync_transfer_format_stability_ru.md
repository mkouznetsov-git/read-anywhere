# Sprint 31 — устойчивость sync/transfer и безопасная подготовка тяжёлых форматов

## Цель

Стабилизировать поведение ReadArc в двух критичных сценариях:

1. источник файла исчезает во время скачивания;
2. CHM/DJVU-адаптеры не должны закрывать приложение при ошибках подготовки.

Также заложена базовая структура `processed_artifacts/` для профессиональной поддержки тяжёлых форматов: DJVU, CHM, DOC/DOCX.

## Скачивание и исчезновение источника

Исправлено поведение, когда Android мог зависнуть, если на Mac удалить файл во время скачивания.

Теперь:

- ожидание первого источника ограничено;
- idle-watchdog скачивания стал короче;
- Direct/LAN stream имеет отдельный timeout;
- если источник видит, что локальный файл исчез, он отправляет `book_file_error` получателю;
- источник удаляет себя из `availableOnDeviceIds` для этой книги и рассылает новый snapshot;
- Android получает терминальную ошибку вместо бесконечного зависания.

Ожидаемое сообщение: файл больше недоступен на устройстве-источнике; нужно включить другое устройство с этой книгой или добавить файл заново.

## CHM/DJVU: crash-safe adapter path

Добавлены защитные контуры:

- глобальные Dart/Flutter error handlers;
- безопасный wrapper открытия rich-reader документов;
- timeout подготовки CHM/DJVU;
- ошибки адаптера возвращают readable error document, а не пробрасываются в UI;
- native tools запускаются через `Process.start` с принудительным kill по timeout.

Это не финальный профессиональный DJVU reader, а стабилизационный слой, чтобы форматные ошибки не закрывали приложение.

## Processed artifacts foundation

В `StorageService` добавлена основа для будущих подготовленных представлений:

```text
ReadAnywhere/
  books/
  processed_artifacts/
    <bookId>/
      artifact.json
      pages/
      text/
      toc.json
```

Архитектурное решение: ReadArc хранит оригинальные файлы, а для тяжёлых форматов создаёт подготовленные артефакты. Это нужно для DJVU/CHM/DOCX, ускорения чтения и будущего полнотекстового поиска.
