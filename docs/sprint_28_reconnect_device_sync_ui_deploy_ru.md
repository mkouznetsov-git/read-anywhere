  - короткий код оставлен как запасной сценарий.

### 3. Повторное подключение отозванного устройства

Проблема: если Android был отозван, повторное подключение через свежий QR не проходило, потому что revocation tombstone в trust registry оставался сильнее нового pairing.

Исправление:

- relay теперь отправляет системное событие `pairing_claimed` владельцу аккаунта после успешного claim кода;
- владелец аккаунта заново доверяет подключаемому устройству через `trustDevice()`, что снимает tombstone для этого `deviceId`;
- после re-trust владелец рассылает новый snapshot;
- повторное подключение ранее отозванного устройства должно проходить по новому QR-коду.

## Нужно ли обновлять relay на сервере?

Да, обязательно.

В Sprint 28 изменён серверный relay: добавлено системное событие `pairing_claimed`, без него повторное подключение ранее отозванного устройства не будет корректно восстанавливать доверие на устройстве-владельце.

Обновление предпочтительно выполнять через GitHub Actions:

```text
GitHub → Actions → Deploy relay → Run workflow
```

Или локально ZIP-архивом:

```bash
scripts/deploy_relay_zip.sh readarc_sprint28_reconnect_sync_ui_deploy.zip
```

После обновления проверить:

```bash
curl https://relay.readarc.ru/health
```

## Как вручную проверить

### Экран синхронизации

1. Открыть «Синхронизация».
2. Проверить, что наверху отображается блок «Устройство».
3. Нажать «Редактировать» у названия устройства.
4. Поменять имя и убедиться, что оно сохранилось.
5. Проверить, что раздела «Дополнительно» нет.
6. Проверить, что QR-кнопки выглядят как основные.

### Повторное подключение отозванного Android

1. На Mac открыть «Синхронизация».
2. Отозвать доступ Android-устройству.
3. Убедиться, что Android видит сообщение об отзыве доступа или перестаёт синхронизироваться.
4. На Mac создать новый QR-код.
5. На Android отсканировать новый QR-код.
6. Ожидаемый результат: Android снова подключается, а на Mac устройство возвращается в список доверенных.

### Relay deploy workflow

1. Запустить `Actions → Deploy relay → Run workflow`.
2. Убедиться, что workflow проходит зелёным.
3. Проверить:

```bash
curl https://relay.readarc.ru/health
```
