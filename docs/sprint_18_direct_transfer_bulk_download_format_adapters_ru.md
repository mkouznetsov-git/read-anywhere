# Sprint 18 — Direct/LAN transfer hardening, bulk download, format adapter cleanup

## Цели

В этом спринте исправлены проблемы с нестабильным и медленным скачиванием, добавлена кнопка скачивания всей библиотеки и убрано отображение бинарных форматов как «кракозябр».

## Скачивание

### Что изменилось

- Direct/LAN endpoint теперь явно требует macOS entitlement `com.apple.security.network.server`, иначе release-приложение на macOS могло не принимать входящие HTTP-подключения.
- Direct/LAN download получает более длинные таймауты для первого ответа и потока данных.
- Relay-fallback больше не должен преждевременно падать с ошибкой «Источник перестал отвечать» во время медленной передачи: watchdog увеличен до 90 секунд.
- В журнале источника теперь видно, сколько Direct/LAN URL было предложено для книги.

### Как проверить скорость

1. Обновить приложение на Mac и Android.
2. Перезапустить приложение-источник на Mac.
3. На macOS при запросе firewall разрешить входящие подключения для ReadArc.
4. Скачать книгу на Android.
5. В статусе должно появляться `Direct/LAN: ... MB/s`.

Если статус остаётся relay-based и скорость около `0.1 MB/s`, значит Android не может достучаться до direct endpoint на Mac. Основные причины: macOS Firewall, разные сети без Tailscale-соединения, запрет входящих подключений для приложения.

## Скачивание всей библиотеки

В верхней панели библиотеки добавлена кнопка `download_for_offline` рядом с кнопкой синхронизации.

При нажатии показывается подтверждение:

```text
Скачать всю библиотеку (<размер>) на это устройство?
Да / Нет
```

Скачивание идёт последовательно, чтобы не перегружать relay/source-устройство.

## Форматы

### DOCX

DOCX теперь открывается в rich-reader, а не как плоский TXT:

- сохраняются абзацы;
- распознаются заголовки `Heading1..Heading6`;
- списки отображаются с маркером `•`;
- сноски/endnotes добавляются как отдельные секции.

Это всё ещё не полноценный Word-layout renderer, но уже не «неформатированный поток текста».

### DOC

Если `.doc` на самом деле является OOXML/DOCX с неверным расширением, он открывается через DOCX-parser. Настоящий legacy binary DOC не показывается как мусорный текст; вместо этого отображается понятное сообщение, что нужен локальный конвертер.

### CHM / DJVU

CHM и DJVU больше не открываются как бинарный текст. Оригинальные файлы сохраняются и синхронизируются, но встроенный просмотр требует отдельного production-адаптера:

- CHM: HTML Help extractor;
- DJVU: DjVuLibre/MuPDF adapter.
