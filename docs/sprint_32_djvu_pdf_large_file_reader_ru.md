# Sprint 32 — DJVU reader и защита больших PDF

## Цель

Sprint 32 переводит DJVU из режима заглушек/небезопасных попыток чтения в отдельный processed-reader pipeline и исправляет зависание при открытии больших PDF-файлов.

## Что изменено

### 1. DJVU больше не открывается через FB2/text fallback

Раньше DJVU шёл через общий rich-reader путь, где адаптер мог читать/рендерить данные слишком тяжело и приводить к закрытию приложения.

Теперь DJVU маршрутизируется в отдельный экран:

```text
_DjvuReaderScreen
```

Он использует processed artifact:

```text
processed_artifacts/<bookId>/artifact.json
processed_artifacts/<bookId>/pages/page_00001.png
processed_artifacts/<bookId>/pages/page_00002.png
...
```

Страницы рендерятся лениво: только те, которые пользователь открывает/прокручивает, а не весь документ сразу.

### 2. DJVU через DjVuLibre

На desktop ReadArc ищет инструменты:

```text
ddjvu
djvused
djvutxt
```

Для macOS дополнительно проверяются типичные пути Homebrew/MacPorts:

```text
/opt/homebrew/bin
/usr/local/bin
/opt/local/bin
```

Если инструменты не найдены, приложение больше не закрывается, а показывает диагностическое сообщение с командой установки:

```bash
brew install djvulibre
```

### 3. CHM переведён в safe mode

CHM-адаптер временно отключён от небезопасного пути открытия. Это сделано специально: приложение не должно закрываться при попытке открыть CHM. Полноценный CHM будет подключаться через processed artifacts отдельным спринтом.

### 4. Большие PDF больше не должны вешать UI при открытии

Исправлены три причины зависаний:

1. ReadArc больше не читает все страницы PDF при открытии только ради геометрии.
   Используется геометрия первой страницы как быстрая оценка.
2. Текстовый слой PDF больше не извлекается синхронно во время открытия.
   Для больших PDF извлечение текста пропускается, чтобы first page показывалась быстро.
3. Рендеринг PDF-страниц поставлен в очередь и ограничен по памяти:
   - Android: меньше DPR, меньше размер страницы, меньше кэш;
   - macOS: умеренный DPR и кэш до нескольких страниц;
   - `cacheExtent` уменьшен, чтобы ListView не запускал рендер слишком многих страниц заранее.

## Relay

Relay не менялся.

Обновлять сервер через SSH/GitHub Actions не нужно.

## Ручная проверка

### DJVU на Mac

1. Установить DjVuLibre:

```bash
brew install djvulibre
```

2. Проверить инструменты:

```bash
which ddjvu
which djvused
which djvutxt
```

3. Запустить ReadArc.
4. Открыть DJVU-файл.
5. Ожидаемо:
   - приложение не закрывается;
   - появляется reader со страницами;
   - страницы подготавливаются лениво;
   - прогресс отображается как `страница / всего`;
   - можно добавить закладку.

### DJVU без DjVuLibre

1. Открыть DJVU на Mac без установленных `ddjvu/djvused`.
2. Ожидаемо: приложение не закрывается, показывается диагностическое сообщение.

### CHM

1. Открыть CHM.
2. Ожидаемо: приложение не закрывается, показывается safe-mode экран.

### Большой PDF 30–50 MB

1. Открыть PDF размером около 34 MB на Mac.
2. Открыть тот же PDF на Android.
3. Ожидаемо:
   - приложение не зависает при открытии;
   - первая страница появляется быстрее;
   - прокрутка не запускает массовый рендер всех страниц;
   - при прокрутке страницы догружаются постепенно.

## Ограничение Sprint 32

DJVU processed pages пока создаются локально на desktop. Синхронизация processed artifacts между устройствами будет отдельным следующим шагом, чтобы Android мог читать уже подготовленный на Mac DJVU без собственного нативного конвертера.
