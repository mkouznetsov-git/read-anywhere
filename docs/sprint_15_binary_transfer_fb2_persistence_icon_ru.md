# Sprint 15 — стабильная передача файлов, FB2 reopen и новая иконка

## Исправлено

### 1. File transfer

Передача книг больше не использует `JSON + base64` для самих chunks. Контрольные события всё ещё идут JSON-сообщениями, но тело chunk передаётся отдельным WebSocket binary frame:

```text
request → offer → accept
binary chunk 0 → encrypted ACK 0
binary chunk 1 → encrypted ACK 1
...
SHA-256 validation
```

Свойства новой схемы:

- encrypted binary frame вместо base64-строки;
- AES-GCM E2E для тела chunk;
- HMAC-подпись заголовка binary frame;
- chunk size 256 KiB для стабильности на Android/Tailscale/Funnel;
- retry одного chunk до 3 раз;
- resume с ближайшей границы chunk;
- понятные ошибки вместо вечного зависания.

Relay по-прежнему не хранит книги: binary frames только ретранслируются между онлайн-устройствами.

### 2. FB2 progress / reopen

Исправлена причина отката FB2 с нового процента на старый при закрытии reader-а.

Проблема была в том, что при dispose reader мог сохранить старый `_pendingUnitIndex`, хотя во время чтения уже был сохранён актуальный `_lastKnownLocator`. Теперь при закрытии приоритет отдаётся последнему подтверждённому locator-у, а текущий unitIndex обновляется при каждом scroll/save.

### 3. Иконка приложения

В assets добавлена выбранная иконка: ноутбук + телефон + книга + единый прогресс чтения в тёплой бежево-коричневой палитре.

Иконки автоматически раскладываются в Android/macOS platform folders при `prepare_flutter_platforms.sh`.

## Проверка

1. Обновить relay до версии 0.1.8.
2. Обновить Mac и Android приложения.
3. Скачать книгу 5–10 MB на Android.
4. Проверить, что статус скачивания показывает прогресс и не зависает на chunk 0.
5. Открыть FB2 на Mac, пролистать с 4.3% до 11%, закрыть, открыть снова.
6. Проверить, что книга открывается около 11%, а не откатывается на 4.3%.
7. Проверить, что Android не возвращает Mac на старый прогресс после sync.
