# Sprint 24 — CHM/DJVU stability, DOCX page view, PDF text copy, FB2 smoothness

## Цели

Спринт закрывает обратную связь по Sprint 23:

1. CHM/DJVU не должны закрывать приложение на macOS.
2. DOCX должен выглядеть ближе к документу Word/Pages/LibreOffice, а не как плоский текст.
3. PDF должен сохранять быстрый fit-width rendering и получить более рабочий текстовый слой для копирования.
4. FB2 на Android должен листаться плавнее.

## Изменения

### CHM

- Для CHM больше не читается весь файл в память перед открытием.
- Нативное извлечение через `extract_chmLib`, `7z`/`7zz`, `unar` осталось, но результат ограничен по количеству HTML-файлов, блоков и размеру картинок.
- Fallback-просмотр теперь читает только небольшой безопасный фрагмент файла и показывает понятное сообщение, если HTML-главы извлечь нельзя.
- Это должно убрать падение macOS-приложения на больших/сжатых CHM.

### DJVU

- DJVU больше не читается целиком в память перед открытием.
- Текстовый слой по-прежнему берётся через DjVuLibre (`djvutxt`/`djvused`), если инструмент установлен.
- Рендер страниц через `ddjvu` стал ограниченным: меньше страниц за раз, ограниченный размер PNG, ограничение на размер page image.
- На Android/iOS без bundled native DjVuLib приложение показывает аккуратный fallback, а не бинарный мусор.

### DOCX

- Экран DOCX теперь выглядит как страница документа: светлый лист, поля, тень, ограниченная ширина, отдельный фон рабочего стола.
- Сохранены таблицы, изображения, заголовки, списки, inline bold/italic/underline.
- Это всё ещё не полноценный Word layout engine. Для абсолютного совпадения с Word/LibreOffice нужен отдельный HTML/PDF-конвертер или embedded layout engine, но текущий вид уже ближе к офисному документу.

### PDF

- Fit-width rendering сохранён.
- Текстовый слой PDF теперь дополнительно извлекает FlateDecode streams, поэтому кнопка копирования должна заработать на большем числе обычных текстовых PDF.
- Для сканов без OCR текстового слоя всё равно не будет — нужен OCR или внешний PDF text engine.

### FB2

- На Android убран тяжёлый `SelectionArea` вокруг всего виртуального списка FB2.
- Скопировать видимый фрагмент по-прежнему можно через кнопку копирования.
- Увеличен cacheExtent, добавлены RepaintBoundary для строк, запись прогресса стала реже, чтобы не мешать скроллу.

## Проверка

```bash
cd apps/flutter_client
flutter clean
flutter pub get
flutter analyze
flutter test
```

Ручной тест:

- открыть большой CHM на macOS — приложение не должно закрываться;
- открыть DJVU на macOS с установленным DjVuLibre — должен появиться текстовый слой или изображения страниц;
- открыть DOCX с таблицей/картинкой/заголовками — должен отображаться как документ на листе;
- открыть текстовый PDF — должна быть доступна кнопка текстового слоя/копирования;
- пролистать большой FB2 на Android — скролл должен быть плавнее.
