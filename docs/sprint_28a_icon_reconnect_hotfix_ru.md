# Sprint 28a — hotfix иконки и повторного подключения после отзыва

## Что исправлено

### 1. Иконка ReadArc

Возвращена утверждённая композиция и палитра иконки: глубокий индиго, тёплое золото, кремовые страницы, круговые стрелки вокруг открытой книги.

Изменение сделано только в нужном месте: буквы `R` и `A` больше не выглядят плоской надписью поверх иконки. Они перерисованы с перспективным искажением по плоскости левой и правой страницы, чтобы восприниматься как напечатанные на листах книги.

### 2. Повторное подключение отозванного устройства

Проблема: если Android был отозван владельцем, при повторном сканировании свежего QR приложение снова получало состояние `Доступ отозван`.

Причина: Android сохранял прежний `deviceId`. Для владельца этот `deviceId` уже имел revocation tombstone. Даже после нового QR старый идентификатор снова совпадал с отозванной записью.

Исправление: если текущее устройство локально находится в состоянии `revoked` и пользователь сканирует новый QR владельца, ReadArc создаёт для этой установки новую device identity:

- новый `deviceId`;
- новый ключ подписи устройства;
- новый fingerprint;
- старую отозванную запись оставляет в истории.

Так повторное подключение становится новым доверием, а не попыткой воскресить старый отозванный идентификатор.

## Обновлять relay на сервере?

Если на сервере уже установлен Sprint 28 relay, для Sprint 28a обновлять relay не обязательно: изменение повторного подключения сделано на клиенте.

Если Sprint 28 relay ещё не был развернут, сервер нужно обновить, потому что Sprint 28 добавлял relay-событие `pairing_claimed`.

Проверка сервера:

```bash
curl https://relay.readarc.ru/health
```

## Проверки

Минимально через GitHub Actions достаточно дождаться зелёной сборки.

Локально при необходимости:

```bash
cd apps/flutter_client
flutter pub get
flutter test
```

Полная проверка:

```bash
cd apps/flutter_client
flutter clean
flutter pub get
flutter analyze
flutter test
```

## Ручная проверка

1. Установить Sprint 28a на Mac и Android.
2. На Mac открыть `Синхронизация`.
3. Отозвать Android.
4. На Android оставить приложение установленным, не удалять данные.
5. На Mac создать новый QR.
6. На Android отсканировать QR.
7. Ожидаемый результат: Android подключается заново; в списке доверенных устройств появляется новая запись Android с новым fingerprint/deviceId, старая отозванная запись остаётся в истории.
