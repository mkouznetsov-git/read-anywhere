# ADR-004: Transport strategy — Official relay, Custom relay, Personal Hub

## Статус

Принято для MVP после отказа от Koyeb/Oracle как обязательного пути.

## Контекст

ReadArc требует интернет-синхронизации без облачного хранения книг. Бесплатные VPS/PaaS часто требуют платёжную карту или недоступны в некоторых регионах. Поэтому архитектура не должна зависеть от одного провайдера.

## Решение

Ввести несколько режимов транспорта:

1. `ReadArc relay` — официальный relay endpoint, когда появится production-сервис.
2. `Custom relay` — любой self-hosted relay пользователя.
3. `Personal Hub / Tailscale Funnel` — relay работает на устройстве пользователя и публикуется через Funnel/Tunnel/VPN.
4. `Local development` — локальный `127.0.0.1:8787` для разработки.

## Последствия

Плюсы:

- разработка не блокируется отсутствием VPS;
- пользователь может выбрать privacy/self-hosted режим;
- будущий официальный relay остаётся совместимым;
- pairing-код сможет переносить endpoint автоматически.

Минусы:

- Personal Hub зависит от доступности выбранного устройства;
- через Tailscale/Cloudflare всё равно используется внешний транспортный сервис;
- нужен следующий спринт pairing, чтобы убрать ручной accountId и URL.
