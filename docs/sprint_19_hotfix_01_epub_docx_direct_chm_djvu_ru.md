# Sprint 19 Hotfix 01 — EPUB/DOCX/Direct-LAN/CHM/DJVU

Дата: 2026-05-08

## Что изменено

1. EPUB
   - Добавлена карта внутренних якорей EPUB (`path`, `path#anchor`, `#anchor`, `anchor`).
   - Внутренние ссылки `chapter.xhtml#id`, `#id`, относительные href через `../` нормализуются к zip-пути.
   - Нажатие на внутреннюю ссылку теперь прокручивает rich-reader к нужному блоку и сохраняет locator.
   - Картинки EPUB продолжают извлекаться из manifest и из HTML `img src`.

2. DOCX
   - DOCX rich-reader теперь читает `word/_rels/*.rels` и достаёт картинки по `r:embed` / `r:id`.
   - Таблицы `w:tbl` отображаются как строки с разделителями ячеек, в порядке документа.
   - Абзацы, заголовки, списки, картинки и таблицы обрабатываются в общем порядке XML-блоков.

3. Direct/LAN
   - Direct endpoint теперь поддерживает `HEAD` для быстрой проверки доступности.
   - Перед скачиванием выполняется быстрый параллельный probe Direct/LAN URL вместо долгого последовательного ожидания.
   - Таймауты соединения снижены: недоступный LAN-кандидат больше не должен подвешивать UI на десятки секунд.
   - Статус изменён на более точный: “Быстро проверяем Direct/LAN…” и “Direct/LAN: соединяемся…”.

4. CHM/DJVU
   - Вместо заглушки теперь открывается текстовый MVP-адаптер.
   - Если удаётся извлечь читаемые строковые фрагменты, файл можно хотя бы просмотреть/искать как текст.
   - Если текст не извлечён, пользователь видит честное сообщение, что нужен локальный converter/renderer.

## Ограничения MVP

- EPUB parser всё ещё regex-based; для production лучше перейти на полноценный Readium/HTML pipeline.
- DOCX таблицы пока не имеют настоящей сеточной вёрстки, а отображаются текстовыми строками.
- DOCX media поддерживает основные embedded image relationships, но не все DrawingML/VML edge cases.
- DJVU/CHM полноценный renderer по-прежнему требует нативных библиотек/конвертеров.
