# Sprint 42A Hotfix 05 — DOCX visible renderer rollback

## Цель

Устранить регрессию, при которой DOCX открывался как пустая бежевая область на macOS и Android.

## Изменения

- DOCX reader больше не использует промежуточный page-wrapper, который мог давать нулевую/невидимую геометрию.
- Восстановлен гарантированно видимый белый лист документа внутри вертикального reader scroll.
- Если логическая ширина DOCX-листа больше экрана, включается горизонтальная прокрутка самого листа.
- Если DOCX парсер не нашёл отображаемых блоков, внутри листа выводится явное диагностическое сообщение, а не пустая область.

## Что не менялось

- PDF / DJVU / EPUB / FB2 / TXT не менялись.
- CHM не менялся.
- Relay не менялся.
- GitHub Actions и версионирование не менялись.

## Relay

Обновлять relay через SSH не нужно.

## Проверки

```bash
cd apps/flutter_client
flutter pub get
flutter analyze
flutter test
flutter build apk --release
flutter build macos --release
```

## Ручная проверка

1. Запустить приложение на macOS: библиотека должна открыться без ошибки manifest.
2. Открыть DOCX: должен появиться белый лист, а не пустой бежевый фон.
3. Повторить на Android.
4. Если вместо документа появится диагностическая строка о пустом DOCX, значит renderer уже видим, а проблема в извлечении блоков из конкретного файла.
