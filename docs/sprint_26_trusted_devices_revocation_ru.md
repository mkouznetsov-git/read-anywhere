# Sprint 26 — доверенные устройства, ключи и отзыв доступа

Sprint 26 переводит список устройств из диагностического UI в основу trust-модели ReadArc.

## Что изменено

### 1. Device identity

Для каждого устройства теперь хранится собственная device identity:

- `deviceId`;
- название устройства;
- публичный ключ устройства `deviceSigningPublicKey`;
- приватный ключ устройства `deviceSigningPrivateKey` — только локально, не входит в sync snapshot;
- fingerprint публичного ключа для отображения пользователю.

Старые manifest-файлы мигрируются автоматически: если ключей устройства нет, они создаются при следующей загрузке manifest.

### 2. TrustedDeviceRecord стал security-записью

Запись доверенного устройства теперь содержит:

- публичный ключ;
- fingerprint;
- роль `owner/device`;
- права `syncMetadata` и `transferFiles`;
- статус `trusted/revoked`;
- дату и причину отзыва доступа.

Поле `deletedAt` оставлено для обратной совместимости, но теперь трактуется как tombstone отзыва доступа.

### 3. Отзыв доступа

На странице «Синхронизация» действие удаления устройства заменено на **«Отозвать доступ»**.

Отзыв доступа:

- сохраняется в manifest как security tombstone;
- синхронизируется через `library_snapshot`;
- не позволяет обычному `lastSeenAt` от старого устройства восстановить доверие;
- блокирует входящие metadata-события от отозванного устройства;
- блокирует binary file chunks от отозванного устройства;
- не позволяет текущему устройству автоматически «самовосстановиться», если его доступ был отозван другим устройством.

### 4. Проверка входящих событий

Клиент теперь проверяет sender device перед обработкой sync-событий:

- события от отозванных устройств отклоняются;
- события от неизвестных устройств отклоняются;
- исключение: первый `library_snapshot` от нового устройства, если он пришёл после QR-pairing, расшифровывается account key и содержит запись о самом устройстве с публичным ключом.

Так сохраняется нормальный UX pairing, но обычные события неизвестных устройств не принимаются.

### 5. UI доверенных устройств

В UI теперь отображаются:

- роль устройства;
- статус доверия;
- fingerprint ключа;
- права metadata/files;
- список отозванных устройств в раскрываемой секции.

Текущее устройство отозвать нельзя. Если текущее устройство получает snapshot, где оно отозвано, синхронизация останавливается и показывается статус «Доступ этого устройства отозван».

## Важные ограничения

Sprint 26 закладывает trust registry и enforcement на клиенте. Следующий security-шаг — перейти от HMAC-подписи account key к полноценной подписи каждого события приватным Ed25519-ключом устройства и проверке по публичному ключу из `trustedDevices`.

Это логично делать вместе со Sprint 27, когда relay начнёт хранить offline queue для encrypted metadata events: у relay появится больше причин проверять envelope-level metadata и отдавать очереди только допустимым устройствам.

## Стратегическая линия после Sprint 26

MVP-этап завершён. Дальше ReadArc развивается как полноценный продукт.

Ключевое архитектурное решение: **ReadArc хранит оригинальные файлы, но для тяжёлых форматов создаёт processed artifacts**.

Это будет основой для последующих спринтов по DOCX/CHM/DJVU, полнотекстовому поиску и ускорению открытия книг на мобильных устройствах.
