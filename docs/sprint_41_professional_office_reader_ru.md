# Sprint 41 — Professional Office Reader для DOCX/DOC

Дата: 2026-05-14

## Цель

Уйти от plain-text представления DOCX/DOC и сделать Office-reader ближе к нормальному просмотру документа: белый лист, реальные поля страницы, табличная сетка, колонтитулы без служебных заголовков, базовые стили Word и выделяемый текст.

## Что изменено

- DOCX теперь рендерится как документная страница, а не как поток текста на бежевой карточке.
- Читаются параметры страницы из `word/document.xml`: размер листа и поля `w:pgSz` / `w:pgMar`.
- Таблицы отображаются без декоративной карточки: с обычными чёрными границами, переносом текста внутри ячеек и распределением ширин по `w:tblGrid` там, где сетка есть в DOCX.
- Колонтитулы больше не добавляются в тело документа как блоки `Верхний колонтитул` / `Нижний колонтитул`; они выводятся как header/footer-области страницы.
- Добавлен разбор базовых paragraph/run properties: выравнивание, отступы, интервалы, размер шрифта, bold/italic/underline, цвет, font family.
- DOCX-текст остаётся в `SelectionArea`, работает выделение и копирование; кнопка «Скопировать текст документа» копирует также header/footer.
- `.doc`, который фактически является DOCX с неправильным расширением, открывается этим же Office-reader.

## Важные ограничения

- Настоящий legacy binary `.doc` по-прежнему открывается через встроенный безопасный OLE/text extractor. Это лучше, чем бинарные «кракозябры», но это ещё не полноценный Word-layout engine.
- Для полного parity с Microsoft Word / LibreOffice для старых `.doc` нужен отдельный native/conversion pipeline. В этот спринт GitHub Actions, релизные имена, relay и серверная часть не менялись.

## Ручная проверка

1. Открыть DOCX с таблицами, колонтитулами и подписями сторон.
2. Сравнить с macOS Preview/TextEdit/Word-like viewer: лист должен быть белым, таблицы — с нормальной сеткой, колонтитулы — внизу/вверху без заголовков «Нижний колонтитул».
3. Проверить выделение текста мышью/тачпадом и копирование через кнопку.
4. Открыть `.docx`, переименованный в `.doc`: он должен использовать тот же DOCX reader.
5. Открыть настоящий старый `.doc`: приложение не должно падать; если layout не извлечён, должен показаться безопасный fallback.
