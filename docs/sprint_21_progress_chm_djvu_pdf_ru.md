# Sprint 21 — прогресс FB2, CHM/DJVU без кракозябр, PDF fit-width

## 1. FB2: синхронизация прогресса по верхней строке

Проблема: на Mac прогресс в библиотеке мог синхронизироваться как 2,4%, но при открытии той же FB2-книги на Android ридер перескакивал на другую позицию и показывал 1,4%.

Причина: старый locator сохранял `unitIndex + unitInBlock`. Эти значения зависят от ширины экрана и переноса строк, поэтому одна и та же верхняя строка на macOS и Android могла получать разные индексы.

Исправлено:

- добавлен стабильный char-anchor для rich-reader units;
- новый FB2 locator: `fb2-unit-anchor-v4`;
- прогресс теперь считается от стабильного `anchorChar / totalChars`, а не от количества отрендеренных строк на конкретном устройстве;
- если старый locator был сохранён на другой ширине экрана, открытие теперь доверяет `progressPercent`, а не wrapped-line индексу.

## 2. CHM

CHM больше не сканируется как произвольный бинарный текст. Старый подход мог находить «похожие на текст» куски внутри сжатого ITSF/LZX-контента и показывать кракозябры.

Теперь CHM adapter:

- извлекает только высоковероятные HTML/TOC/Index-фрагменты;
- не делает произвольный binary string scan;
- проверяет итоговый preview на читаемость;
- если безопасно извлечь главы нельзя, показывает понятное сообщение вместо бинарного мусора.

Полноценный CHM viewer всё ещё требует нативный CHM/LZX adapter.

## 3. DJVU

DJVU больше не открывается как сырой текст. Это графический бинарный формат; без DjVuLibre/нативного renderer попытка текстового preview даёт кракозябры.

Теперь ReadArc показывает честный экран-заглушку и сохраняет/синхронизирует оригинальный файл.

## 4. PDF: fit-width

PDF-reader переведён с generic `PdfView` на собственный fit-width renderer:

- каждая страница рендерится в изображение ровно под ширину доступной области;
- на телефоне и desktop страница занимает всю ширину экрана;
- вертикальная прокрутка остаётся обычной;
- прогресс PDF сохраняется по текущей странице;
- текстовый PDF по-прежнему имеет отдельный selectable text-layer и кнопку копирования текста.

## Проверка

```bash
cd apps/flutter_client
flutter pub get
flutter analyze
flutter test
```

Ручная проверка:

1. Открыть FB2 на Mac, дойти до 2–3%, дождаться синхронизации, открыть на Android — позиция и процент не должны откатываться назад из-за другой ширины экрана.
2. Открыть CHM — не должно быть бинарных кракозябр; либо читаемый preview, либо нормальное сообщение.
3. Открыть DJVU — должен быть экран с объяснением, а не бинарный текст.
4. Открыть PDF на Android/macOS — страница должна быть растянута по ширине экрана.
5. Для текстового PDF проверить кнопку «Текстовый слой PDF» и выделение/копирование текста в этом режиме.
