# Sprint 5 Hotfix 03 — стабильный вертикальный TXT-reader

## Проблема

Hotfix 02 сделал `PageView` с логическими TXT-страницами, но `PageView` был горизонтальным, а внутри каждой логической страницы оставался `SingleChildScrollView`.

Из-за этого пользователь вертикально листал только содержимое одной логической страницы. На практике казалось, что книга состоит из 1–2 экранов, хотя остальные логические страницы были доступны только горизонтальным свайпом.

## Исправление

TXT-reader переведён на вертикальные страницы:

- `PageView.builder(scrollDirection: Axis.vertical)`;
- убран вложенный `SingleChildScrollView`, который перехватывал вертикальное листание;
- размер логической страницы теперь рассчитывается по текущему viewport;
- locator сохраняет не pixel-scroll и не только pageIndex, а `anchorChar` — позицию символа в исходном тексте;
- при открытии на другом устройстве `anchorChar` мапится на ближайшую страницу для экрана этого устройства.

## Новый locator

```json
{
  "type": "txt-page-v2",
  "pageIndex": 12,
  "pageCount": 250,
  "anchorChar": 18420,
  "startChar": 18420,
  "endChar": 19880,
  "totalChars": 380000,
  "progressPercent": 4.84
}
```

## Ожидаемое поведение

- книга листается вверх/вниз по всей длине;
- закрытие и повторное открытие возвращает к той же странице;
- синхронизация между устройствами возвращает к тому же фрагменту текста;
- процент считается от `anchorChar / totalChars`, поэтому не должен прыгать между 5% и 3.8% при повторном открытии.

## Проверка

1. Открыть длинный TXT.
2. Листать вертикально больше чем на 10–20 страниц.
3. Закрыть reader.
4. Открыть reader снова.
5. Проверить, что открылась та же страница.
6. Подключить второе устройство.
7. Открыть книгу там и проверить, что открывается тот же фрагмент текста.
