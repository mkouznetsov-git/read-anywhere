# Sprint 29 — надёжная синхронизация библиотеки после добавления книг

## Что исправлено

После подключения Android к библиотеке новые книги, добавленные на Mac, могли не появляться на Android без ручного переподключения/повторного pairing. Основная причина — metadata sync слишком сильно полагался на одноразовую доставку `library_snapshot` через WebSocket. Если мобильный клиент в этот момент кратковременно ушёл в background, сеть переключилась или WebSocket выглядел подключённым, но фактически пропустил сообщение, Android мог не запросить актуальный snapshot повторно.

В Sprint 29 добавлены защитные механизмы:

1. При подключении клиент явно запрашивает durable offline queue у relay через `offline_queue_pull`.
2. После подключения выполняется несколько повторных pull/request попыток.
3. Пока приложение подключено, раз в 15 секунд оно запрашивает offline queue и актуальный metadata snapshot.
4. После важных локальных изменений (`book_imported`, удаление книги, отзыв устройства, изменение имени устройства) snapshot отправляется не один раз, а с короткими retry через 2 и 8 секунд.
5. Retry не зацикливаются: snapshot с `_retry_` не планирует новые retry.

## Почему это важно

ReadArc теперь не рассчитывает на идеальную одноразовую доставку metadata-событий. Даже если Android пропустил моментальное событие от Mac, он должен получить новые книги через:

- live WebSocket broadcast;
- durable offline queue;
- периодический metadata pull;
- повторную отправку snapshot после важных изменений.

## Что не менялось

- Формат relay API не менялся.
- Схема хранения offline queue на сервере не менялась.
- Binary file transfer не менялся.
- Иконки/branding не менялись.
