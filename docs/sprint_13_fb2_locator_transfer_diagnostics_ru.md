# Sprint 13 — FB2 locator v2 и диагностика скорости передачи

## Что исправлено

### FB2 progress / reopen

Предыдущий FB2-reader сохранял позицию как абсолютный `unitIndex`. Это было недостаточно стабильно: при пересчёте ширины, при наличии картинок и при разных платформах один и тот же процент мог указывать на старый индекс.

Новый locator:

```json
{
  "type": "fb2-unit-anchor-v2",
  "unitIndex": 120,
  "unitCount": 3200,
  "blockIndex": 48,
  "unitInBlock": 3,
  "progressPercent": 3.75
}
```

Главный якорь теперь не абсолютный индекс, а пара:

```text
blockIndex + unitInBlock
```

Это должно исправить сценарий:

```text
открыли FB2 на 4.3%
пролистали до 6.1%
закрыли
в библиотеке 6.1%
снова открыли — попали на 6.1%, а не на 4.3%
```

### Дребезг scroll bar в FB2

Для FB2-list теперь используется `itemExtentBuilder`, чтобы Flutter заранее знал точную высоту каждой строки/картинки. Это должно уменьшить скачки ползунка при drag-scroll на macOS.

Также убран общий `SelectionArea` вокруг всего списка. Выделение текста осталось построчно через `SelectableText.rich`, но оно больше не оборачивает весь scrollable-контейнер.

## Передача файлов

MVP file-transfer всё ещё идёт через JSON/base64 + E2E envelope. Это безопасно, но не оптимально по скорости.

В этом спринте:

```text
chunk size: 1 MiB → 2 MiB
relay max message: 8 MiB → 16 MiB
UI показывает примерную скорость MB/s во время отправки/скачивания
```

Если после этого книга 6 MB всё ещё скачивается десятки секунд, следующий системный шаг — не увеличивать chunk дальше, а делать отдельный binary file-transfer protocol:

```text
WebSocket binary frames или HTTP one-time download через encrypted stream
без JSON/base64 удвоения
с отдельными ACK/resume
```

## Проверка

2. Открыть FB2, пролистать с 4% до 6%, закрыть.
3. Убедиться, что в библиотеке 6%.

5. Проверить то же на Android.
6. Прокрутить FB2 на macOS за scrollbar — дребезг должен быть заметно меньше.
7. Скачать книгу 5–10 MB и посмотреть скорость MB/s в статусе.
