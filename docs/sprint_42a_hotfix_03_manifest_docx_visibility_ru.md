# Sprint 42A Hotfix 03 — восстановление manifest и видимый DOCX page renderer

## Причина

После Sprint 42A Hotfix 02 на macOS проявилась повреждённая локальная `manifest.json` с лишней закрывающей скобкой. Приложение корректно показало ошибку, но не восстановило библиотеку автоматически. На Android DOCX продолжал открываться пустой страницей: масштабирование страницы через `Transform.scale` оказалось рискованным для текущей связки `ListView`/page renderer на мобильном.

## Исправления

### Manifest

- `StorageService.loadManifest()` теперь умеет восстанавливаться после частично повреждённой `manifest.json`.
- Если JSON содержит валидный объект и лишние символы после него, ReadArc обрезает хвост, сохраняет восстановленный manifest и продолжает запуск.
- Если текущий manifest не восстановить, ReadArc пытается взять последний валидный файл из `manifest_backups`.
- Повреждённый manifest сохраняется в `manifest_recovery`, чтобы можно было диагностировать проблему без потери данных.
- `saveManifest()` переведён на запись через временный файл с последующей заменой, чтобы снизить риск частичной записи.

### DOCX renderer

- Убран mobile-risky `Transform.scale` вокруг Office-страницы.
- DOCX-страница теперь масштабируется через реальные размеры виджетов: ширина страницы, поля, шрифты, таблицы и отступы уменьшаются пропорционально.
- Это сохраняет фиксированную листовую модель и должно вернуть видимость страницы на Android.

## Что не менялось

- PDF / DJVU / EPUB / FB2 / TXT.
- EPUB internal links.
- CHM.
- Relay.
- GitHub Actions / версионирование сборок.

## Relay

Обновлять relay через SSH не нужно.

## Ручная проверка

1. Запустить macOS-приложение с существующей библиотекой.
2. Убедиться, что ошибка `FormatException: Unexpected character ... }` больше не блокирует запуск.
3. Открыть `Договор_поставки.docx` на Android.
4. Проверить, что вместо пустой бежевой области виден белый лист документа.
5. Проверить, что лист масштабирован под ширину экрана и текст не рефлоуится как обычная EPUB/FB2-страница.
