# Sprint 23 — релизы, Android-обновления и QR-pairing

## Что изменено

### 1. Инкремент snapshot-сборок

Скрипты сборки больше не называют все артефакты одинаково `ReadArc-0.1.0-*`.

Для push/workflow_dispatch сборок используется номер запуска GitHub Actions:

- `ReadArc-0.1.0-snapshot.<run_number>-android-universal-release.apk`
- `ReadArc-0.1.0-snapshot.<run_number>-macos-release.dmg`

Для тегов `v*` используется версия из тега, например `v0.1.4` → `ReadArc-0.1.4-*`.

Android build number также получает `github.run_number`, чтобы APK можно было ставить поверх предыдущей сборки.

### 2. Очистка старых Read Anywhere релизов

Workflow при публикации релиза удаляет legacy-релизы и assets с именами `Read Anywhere`, `ReadAnywhere`, `read_anywhere`, `read-anywhere`.

Для rolling-релиза `main-latest` workflow теперь также удаляет старые assets перед загрузкой новых, чтобы страница релиза не превращалась в свалку старых snapshot-файлов.

### 3. Android-обновления без удаления приложения

Для внутренних sideload-сборок добавлен стабильный dev signing key:

`assets/signing/readarc-dev-upload.jks`

Это не production-ключ. Он нужен только для тестовых APK из GitHub Actions, чтобы Android видел новые сборки как обновление того же приложения, а не как чужой APK с другой подписью.

Важно: если на устройстве уже стоит APK, подписанный другим ключом, один раз всё равно придётся удалить старую версию. После установки новой Sprint 23-сборки следующие Sprint 23+ сборки должны обновляться поверх.

### 4. QR-код подключения

QR-приглашение обновлено до формата v2. Теперь в нём есть всё необходимое для подключения нового устройства:

- relay/connection URL;
- режим соединения;
- 6-значный код;
- accountId;
- ownerDeviceId;
- название устройства-владельца;
- ключ шифрования аккаунта;
- время истечения приглашения.

На новом устройстве больше не нужно заранее выбирать `Personal Hub / Tailscale Funnel`. Достаточно нажать “Сканировать QR”.

### 5. Ошибка `Pairing code is invalid or expired`

Добавлен fallback для QR-v2: если relay по какой-то причине не принимает короткий код, но QR содержит полный защищённый invite и он ещё не истёк, приложение всё равно подключит аккаунт по данным из QR.

Это закрывает сценарии:

- relay был перезапущен после генерации кода;
- Tailscale/Funnel endpoint был исправлен между созданием и сканированием QR;
- Android сначала попал не в тот relay;
- короткий код исчез из in-memory relay, но пользователь физически сканирует свежий QR.

Ручной 6-значный код по-прежнему требует relay, потому что он не содержит ключ аккаунта.
