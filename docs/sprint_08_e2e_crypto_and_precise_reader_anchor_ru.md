# Sprint 8 — E2E-шифрование sync-событий и точный TXT locator

## Что добавлено

### E2E payload encryption MVP

Все пользовательские sync-события теперь отправляются с зашифрованным payload:

- `library_snapshot`
- `library_snapshot_requested`
- `book_file_requested`
- `book_file_offer`
- `book_file_accept`
- `book_file_chunk`
- `book_file_error`
- `book_file_cancelled`

Relay по-прежнему видит технический envelope:

- `type`
- `accountId`
- `deviceId`
- время сообщения

Но содержимое `payload` передаётся как `e2ee`-объект:

```json
{
  "e2ee": {
    "v": "readarc-e2e-v1",
    "alg": "AES-256-GCM",
    "nonce": "...",
    "ciphertext": "...",
    "mac": "..."
  }
}
```

Для MVP используется общий ключ аккаунта `accountEncryptionKey`, который хранится локально в `manifest.json` и не входит в обычный `library_snapshot`.

### Pairing и ключ

QR/invite-ссылка теперь содержит:

- relay URL;
- pairing code;
- название устройства, которое создаёт приглашение;
- ключ аккаунта для расшифровки будущих sync-событий.

Это позволяет новому устройству после сканирования QR сразу подключиться к тому же аккаунту и расшифровывать события.

Для fallback-варианта с ручным 6-значным кодом relay временно хранит ключ в RAM вместе с pairing-записью. Это удобно для разработки, но для production нужно заменить на PAKE/публичные ключи устройств, чтобы relay вообще не видел ключ даже во время ручного pairing.

### Журнал событий

Журнал на экране синхронизации теперь скрыт под раскрывающейся стрелкой и не занимает экран постоянно.

### TXT top-anchor v3

TXT-reader теперь сохраняет не просто ближайший блок, а более точный символ у верхней границы экрана:

```json
{
  "type": "txt-top-anchor-v3",
  "anchorChar": 18420,
  "totalChars": 380000,
  "chunkIndex": 35,
  "chunkCount": 720,
  "scrollOffset": 12345.6,
  "maxScrollExtent": 90000.0,
  "viewportWidth": 512.0,
  "progressPercent": 4.84
}
```

При восстановлении позиции приложение пытается поставить именно этот символ/строку к верхней границе reader-а. Это должно стабилизировать возврат к месту чтения на том же устройстве и между Mac/Android.

## Ограничения

Это MVP-E2E, а не финальная модель доверия:

1. Envelope metadata пока открыта relay-у.
2. 6-значный ручной код передаёт ключ через RAM relay.
3. Нет подписи событий устройствами.
4. Нет защиты от replay на уровне monotonic sequence/signature.
5. Нет индивидуальных device public keys.

Следующий security-слой должен добавить device keys, подписи, key rotation и отзыв ключа устройства.

## Что обязательно проверить

1. Обновить клиент и relay до этого спринта.
2. Создать QR-код подключения на Mac.
3. Подключить Android через QR.
4. Добавить книгу на Mac и проверить, что Android видит её.
5. Скачать книгу на Android.
6. Пролистать TXT до узнаваемой строки, закрыть, открыть снова.
7. Проверить, что сверху снова та же строка.
8. Проверить то же между устройствами.
9. В логах relay убедиться, что сообщения проходят, но payload в WebSocket уже не содержит открытый manifest/chunks.
